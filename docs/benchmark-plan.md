# Frozen ScienceQA CPU benchmark v1

Claim to test: real pinned SmolVLM multiple-choice accuracy and CPU latency/throughput/memory on an owned frozen subset of published ScienceQA image-bearing questions. This is a small educational science VQA sample, not a general VQAv2 score or evidence of state-of-the-art quality. No speedup is claimed without matched repeated before/after evidence and a separate source-mapped profile.

## Dataset and held-out boundary

Use [ScienceQA by Lu et al., NeurIPS2022](https://github.com/lupantech/ScienceQA/tree/2cbf8318e07b9ece895bb2ae605e71e38d623264), official revision`2cbf8318e07b9ece895bb2ae605e71e38d623264`. Its [official dataset license](https://github.com/lupantech/ScienceQA/blob/2cbf8318e07b9ece895bb2ae605e71e38d623264/LICENSE-DATA) is CC BY-NC-SA4.0. Image bytes are obtained from [derek-thomas/ScienceQA](https://huggingface.co/datasets/derek-thomas/ScienceQA/tree/f18b0a70359ebfb41f658fd564208d0355b013f4), revision`f18b0a70359ebfb41f658fd564208d0355b013f4`. That mirror's card header differs from the official license; follow the official stricter noncommercial/share-alike license. Its converter source also names that official license. The preparation command preserves the license and source URLs and verifies pinned parquet SHA-256 from Git LFS identifiers. It cross-checks every row's question, choices, answer, hint, subject, topic and grade against the official split and original numeric insertion order. It does not execute third-party dataset code.

`uv run --frozen python tools/prepare-vqa-benchmark.py --download` explicitly downloads about280MB under ignored`.tooling/scienceqa/`, with per-file byte bounds, checksums, network timeouts and10GiB disk reserve. App launch never downloads. Freeze16 official-validation and128 official-test image questions by sorting SHA-256 of`scienceqa-benchmark-v1/{split}/{source_id}` ascending. Retain input-limit exclusions and selection provenance. No training questions enter either subset. Validation and profiling must finish before the final test campaign. Do not tune model, prompt, scorer, subset or generation settings on final held-out predictions. Model pretraining contamination is unknown and must be reported. Gold, lecture, solution, captions and topic/grade metadata never reach generation. Original public hint, question, choices and image are legitimate model inputs.

## Real-product path and controls

Reuse the owned Flask launcher and HTTP API via`tools/verify-trialdesk.py`; each eight-question batch gets a fresh workspace, uploads canonical PNG annotations, freezes a manifest, starts actual CPU generation, polls terminal state and exports full provenance. Keep product64-item and600-second model-process limits. Five repeats alternate original/reversed input order; each fresh workspace must report zero cache hits and every item must traverse the real vision encoder. Deterministic greedy repeats measure latency variance, not five independent quality samples. Match a seeded uniform-choice baseline on the exact same questions for seeds0..4 and report theoretical chance expectation. Report actual accuracy and Wilson95% interval over unique questions, invalid/unrecognized answers, subject counts and all failed/partial/timed-out items. Never assert generated wording or discard wrong answers. A second simultaneous run is explicitly offered and must be visibly rejected as busy, recording run admission separately from item completions.

The model remains`HuggingFaceTB/SmolVLM-256M-Instruct`, revision`7e3e67edbbed1bf9888184d9df282b700a323964`, Apache2.0. The existing explicit allowlisted download and hash-verified manifest are reused. Generation is the shipped deterministic32-token maximum with eager CPU float32 and four PyTorch threads; prompts/scorer are unchanged. Provision a dedicated model environment, never mutate shared local ML tooling. Manual workflow`vqa-benchmark.yml` pins the previously exercised PyTorch2.11.0, torchvision0.26.0, Transformers5.20.2, safetensors0.8.0 and Pillow13.0.0, records the resolved freeze and uses no API credentials or remote code.

Record per-item actual generation/item seconds and output token count, batch end-to-end seconds including cold model startup, median/range across five repeats, p50/p95/p99/min/max item latency, items/s and tokens/generation-second. The runner reports Linux process peak RSS and CPU time, real pixel shape/vision forwards and model startup duration including imports/loading. GPU is unused. Each batch starts a new model process, so report this cold-process policy explicitly. OS file cache is not flushed; later repeats may benefit. No confidence probabilities are exposed by the shipped model interface, so calibration is unavailable rather than fabricated. Evidence includes source SHA/dirty state, runtime versions, CPU/hardware, immutable manifest/model hashes and complete raw predictions/exports. The isolated runner has a five-hour campaign ceiling and340-minute workflow ceiling. Failures retain partial evidence and cleanup.

## Commands and profiling

First run `uv run --frozen python tools/test-vqa-benchmark.py` and `uv run --frozen python tools/verify-trialdesk.py benchmark-smoke --ci --port 8432 --benchmark-vqa smoke`. Smoke explicitly removes model configuration from the owned server and checks visible model-unconfigured failure, annotation/freeze/export and cleanup; it makes no inference or quality claim.

With explicit`VQA_MODEL_PATH` and`VQA_MODEL_PYTHON`, run`uv run --frozen python tools/verify-trialdesk.py benchmark-validation --ci --port 8432 --benchmark-vqa .tooling/scienceqa/validation-manifest.json`, then dispatch the profile stage. That stage sets `VQA_PROFILE_DIR` and executes only the first eight frozen validation questions once. It retains Python cProfile plus at most eight native [PyTorch2.11 CPU profiler](https://docs.pytorch.org/docs/2.11/profiler.html) tables around unchanged `model.generate` calls. The ordinary path uses `nullcontext`, with no profiler or report writes. Native tables group operators by input shape, sort self CPU time, cap output at100 rows and track tensor allocation/deallocation inside generation. Headers record item index/UUID, Torch version/build and existing thread counts. No Chrome trace, tensor values, questions/gold or model weights are exported. Model loading is outside the native context; process RSS remains the separate whole-process measure.

All profiler samples are excluded from performance summaries: shape/memory instrumentation adds overhead and may retain tensor references. Native tables complement cProfile's coarse C-call timing; they do not establish an optimized backend or a performance win. Model/prompt/generation/dtype/eager-attention/thread settings remain unchanged. Inspect actual operator/shape/memory receipts before selecting a runtime fix. `tools/test-vqa-benchmark.py` verifies normal/profile routing, eight-table/100-row bounds, metadata and absence of gold with a stubbed profiler/model; it never performs real inference. After source/profile review, run the exact final command with unique name`benchmark-test` and`test-manifest.json`, or manually dispatch stage`test`. No locally timed campaign is authorized without main's resource grant.

Retain`.audit/verification/<run>/benchmark.json`, per-batch exports, progress/failure evidence,`result.json`, server logs and official dataset license after owned cleanup. Raw images, model weights and downloaded parquet do not belong in Git. Curate aggregate results/hashes and link artifacts in README after main inspects the actual evidence. A failed/profile/smoke run cannot support a speed or quality claim.
